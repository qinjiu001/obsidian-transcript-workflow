## 中间的“Agent执行说明书”只回答七个问题（给人工看的，codex不用看）

每个任务节点都填写：

1. **输入是什么？**
2. **输出是什么？**
3. **必须执行什么？**
4. **允许Agent自己判断什么？**
5. **怎样判断结果合格？**
6. **发生异常怎么办？**
7. **什么情况必须停下来问人？**


## 节点：播客文稿编辑

**输入：**

- 一个DOCX文件路径；
- 输出语言：简体中文；
- 处理模式：obsidian文章。

**MUST：**

- 先输出有效Markdown的obsidian文章，不要去把文章的字数控制在某一个标准字数限定之内
- 如果博客的文稿内容很多，那也要继续保持文章内容按照输出结构来输出
- 文档里面涉及Mermaid 流程图的生成，用我们的mermaid-visualizer这个skills去帮助生成
- 输出目录必须使用 `raw/02-papers`，并保持源文档的相对分类目录
- YAML 不要生成 `source_type`、`language`、`status`、`human_sop` 和 `cssclasses`
- 来源、节目、嘉宾、时长等信息只保留在 YAML，不要在正文开头重复生成“基本信息”

**SHOULD：**

- 核心判断不强制规定为三个，因为有时候博客文稿比较长，例如超过30分钟的时候，他的核心判断就肯定会超过三个，这个时候就是有几个核心判断就输入几个

**验收标准：**

- 读者不需要听原播客也能理解；
- 文章不是只有几百字的简单摘要；
- 没有明显重复和口语化干扰；
- 没有虚构内容。

**停止条件：**

- 原文严重缺失，这个要单独列举出来，让人工去重新提供完整的文档
- 无法识别人名或关键概念；
- 文档无法读取。
- 文档太长codex觉得处理
