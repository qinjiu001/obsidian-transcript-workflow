### 运行中发现的问题

- **最费时间的步骤：** 把 Human SOP、Skill 规则、Workflow、路径配置和跨 Agent 交接要求逐项对齐，避免同一规则在不同文件中出现冲突。
- **最容易出错的步骤：** 区分“已经由人工确认的稳定规则”和“只写在迭代记录中的观察”。如果不区分，Agent可能把尚未批准的想法直接写入 Skill。
- **Token消耗最大的步骤：** 完整读取 Skill 及其参考文件，并生成一份不依赖 Codex Skill 机制的自包含 WorkBuddy 交接文档。
- **原规则中缺失的判断：**
  - Human SOP 同时存在“长文也要完整处理”和“文档太长时停止”两条规则，但没有规定明确边界。
  - 没有说明 WorkBuddy 是否能访问相同的本地磁盘、Python、Obsidian 和 Codex Skill 目录。
  - 没有规定跨 Agent 第一次试跑成功后，谁负责把结果标记为“完成回归测试”。
- **Agent做出的临时假设：**
  - WorkBuddy 与 Codex 在同一台 Windows 电脑上运行，并能访问 `E:`、`F:` 和 `C:` 路径。
  - WorkBuddy 不能自动加载 Codex 的 `SKILL.md`，因此交接文档必须自包含。
  - 长文优先采用完整提取和分段处理；只有确认无法保持完整证据覆盖时才停止询问人工。
